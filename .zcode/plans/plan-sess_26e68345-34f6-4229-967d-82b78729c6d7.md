# eCG Auth Integration Plan

## Overview

Integrate eCG Auth as the primary authentication backend while maintaining backward compatibility with existing Supabase Auth. New registrations go to eCG Auth. Existing users are migrated on successful legacy login. Backend routes proxy eCG Auth calls. 2FA is gated behind `ECG_AUTH_2FA_ACTIVE=false`.

## New Files (4)

### 1. `server/src/services/ecgAuth.service.ts` — eCG Auth HTTP client

Central service that wraps all eCG Auth API calls. Every call sends `X-API-Key` header. Reads env vars `ECG_AUTH_BASE_URL` and `ECG_AUTH_API_KEY`. Never throws — returns `{ ok, data, error, status }` tuples so callers can decide fallback behavior.

**Exports:**
- `isEcgAuthConfigured()` — returns false if BASE_URL or API_KEY missing (graceful degradation)
- `ecgLogin(email, password, emailHtml?)` — `POST /auth/login`
- `ecgRegister(email, password, firstName, lastName)` — `POST /auth/register`
- `ecgVerify2fa(pendingToken, code)` — `POST /auth/2fa/verify`
- `ecgResend2fa(pendingToken, emailHtml?)` — `POST /auth/2fa/resend`
- `ecgVerifyToken(token)` — `POST /auth/verify`
- `ecgRefreshToken(refreshToken)` — `POST /auth/refresh`
- `ecgLogout(userId, refreshToken?)` — `POST /auth/logout`
- `ecgGetProfile(userId)` — `GET /auth/profile`
- `ecgChangePassword(userId, currentPassword, newPassword)` — `POST /auth/password/change`
- `ecgForgotPassword(email, resetUrl, emailHtml?)` — `POST /auth/password/forgot`
- `ecgResetPassword(token, newPassword)` — `POST /auth/password/reset`
- `buildBrandedResetEmailHtml(resetUrl, token)` — returns branded HTML using existing eComGear email template with `{{resetUrl}}` and `{{token}}` placeholders
- `buildBrandedOtpEmailHtml()` — returns branded HTML for 2FA OTP with `{{code}}` placeholder

### 2. `server/src/routes/ecgAuth.routes.ts` — New backend auth routes

These are the routes the frontend will call instead of going directly to Supabase. Mounted at `/api/v1/auth/ecg/*` in app.ts.

**Endpoints:**

| Method | Path | Logic |
|--------|------|-------|
| `POST` | `/login` | **Primary login flow** (see detailed flow below) |
| `POST` | `/register` | **New registration** — always registers on eCG Auth, then provisions workspace (Supabase profile + org + project) using the returned user ID as `ecg_auth_user_id` reference |
| `POST` | `/2fa/verify` | Verify 2FA code (gated by `ECG_AUTH_2FA_ACTIVE`) |
| `POST` | `/2fa/resend` | Resend 2FA code (gated by `ECG_AUTH_2FA_ACTIVE`) |
| `POST` | `/forgot-password` | **Forgot password with dual path** (see flow below) |
| `POST` | `/reset-password` | Reset password using eCG Auth token |
| `POST` | `/change-password` | Change password for authenticated user |
| `POST` | `/refresh` | Refresh eCG Auth access token |
| `POST` | `/logout` | Logout — calls eCG Auth logout + clears Supabase session if exists |

### 3. `server/src/middleware/ecgAuth.middleware.ts` — Auth middleware with eCG Auth fallback

New `ecgAuthMiddleware` that first tries eCG Auth verify, falls back to Supabase Auth verify. This is the drop-in replacement for `authMiddleware` — used in `ecgAuth.routes.ts` and eventually all routes.

### 7. `src/pages/Auth.tsx` — Frontend login/signup/forgot-password changes

**Login (`handleLogin`):**
1. POST to `/api/v1/auth/ecg/login` (backend) instead of `supabase.auth.signInWithPassword`
2. Backend tries eCG Auth first
3. If eCG Auth returns `requires2fa`, show 2FA code input (only if `ECG_AUTH_2FA_ACTIVE` response flag present)
4. If eCG Auth login succeeds, store returned `accessToken`/`refreshToken`, navigate as before
5. Backend handles the legacy fallback transparently (frontend doesn't know/care)

**Signup (`handleSignup`):**
1. POST to `/api/v1/auth/ecg/register` (backend) instead of `supabase.auth.signUp`
2. Backend registers on eCG Auth, provisions workspace, returns `{ session, projectId }`
3. Frontend stores eCG Auth tokens, navigates to project

**Forgot Password (`handleForgotPassword`):**
1. POST to `/api/v1/auth/ecg/forgot-password` (backend)
2. Backend handles dual path (ecg auth vs legacy), frontend doesn't change UX

**New state variables:**
- `ecgAccessToken` / `ecgRefreshToken` stored in localStorage (key: `ecg-auth-tokens`)
- `pending2faToken` for 2FA flow

## Detailed Flows

### Login Flow (Backend `POST /api/v1/auth/ecg/login`)

```
Request: { email, password }
          ↓
    Is eCG Auth configured?
     YES → POST /auth/login to eCG Auth
           ↓
      Success? → Return { accessToken, refreshToken, user }
      requires2fa? → Return { requires2fa: true, pendingToken }
      AL-0003 (no account)? → Fall through to legacy
      AL-0004 (wrong password)? → 
        Check if user has ecg_auth_user_id in profiles
          HAS it → Return error "Wrong password. Try unified password change."
          DOESN'T have it → Fall through to legacy
          ↓
      Other error → Fall through to legacy
     NO → Skip directly to legacy
          ↓
    LEGACY: supabase.auth.signInWithPassword(email, password)
           ↓
      Success? → Register user on eCG Auth (fire-and-forget)
                 Store ecg_auth_user_id in profiles table
                 Return { accessToken: sb_access_token, refreshToken: sb_refresh_token, user, migrated: true }
      Failure → Return 401 with error message
```

### Register Flow (Backend `POST /api/v1/auth/ecg/register`)

```
Request: { email, password, fullName, organizationName, projectName }
          ↓
    POST /auth/register to eCG Auth
           ↓
    Success (201) → Create Supabase user (admin API) to maintain profile/org/project tables
                    OR just create profile with ecg_auth_user_id = eCG user ID
                    Create org, org_members, project (same as signup-complete edge function)
                    Return { accessToken, refreshToken, user, projectId }
    409 (email exists on eCG Auth) → 
      Check profiles table for ecg_auth_user_id match
        Found → Return error "Account already exists. Please log in."
        Not found → Return error "Account already registered. Try logging in or use forgot password."
```

### Forgot Password Flow (Backend `POST /api/v1/auth/ecg/forgot-password`)

```
Request: { email }
          ↓
    Look up user in profiles by email
          ↓
    Has ecg_auth_user_id?
      YES → POST /auth/password/forgot to eCG Auth
            with resetUrl = `${FRONTEND_URL}/auth/reset-password`
            with emailHtml = branded eComGear template (using {{resetUrl}} and {{token}} placeholders)
            Return success (always 200 to prevent enumeration)
      NO → Use legacy Supabase resetPasswordForEmail + branded edge function email
           Return success
```

### Wrong Password Message

When a user has `ecg_auth_user_id` set but enters wrong password on eCG Auth:
```json
{ 
  "error": "invalid_credentials",
  "message": "This email is registered with a unified eCG account. Please use the password you use on other eCG apps like Mirofish, OneNET, or eComGear, or use 'Forgot Password' to reset it."
}
```

## What Stays Unchanged

- **Google OAuth** — stays with Supabase (eCG Auth doesn't support OAuth providers)
- **Dashboard Access** — stays with its own JWT system (separate from user auth)
- **Admin login** — stays with Supabase for now (admin users are a small set)
- **Existing `authMiddleware`** — NOT modified; new `ecgAuthMiddleware` is used only for eCG auth routes
- **Edge functions** — `signup-complete`, `confirm-email`, `password-reset`, `welcome` all stay for legacy users

## Feature Flags

| Flag | Default | Purpose |
|------|---------|---------|
| `ECG_AUTH_2FA_ACTIVE` | `false` | Gates 2FA flow in login + register. When false, 2FA endpoints return 404 and `requires2fa` responses are ignored |
